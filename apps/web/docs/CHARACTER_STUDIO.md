# Character Studio (manga & webtoon characters)

The owner's "Manga & Webtoon Character Studio" brief, rewritten to fit this repo and to be buildable one phase per
session. Paste the **Session prompt** (end of this file) with the phase number to start a phase. Status at the end.

## 2. Rules (in addition to CLAUDE.md)

- Pure modules (`src/character/**`, no React, no store, no DOM except `render/toSvg.ts` string output) are unit tested
  first. The slice only orchestrates; components only render and call actions.
- The studio renders **SVG DOM** (no Fabric for rigs, no second Fabric canvas). The board gets characters as Fabric
  objects through `loadSVGFromString`.
- Persistence only through `@/lib/storage` (`characterStorage`, IndexedDB, key `characterLibrary`).
- Data tables (poses, recipes, garments, hair) are listed in `fileBudget.test.ts` `DATA_FILES`.
- A public type change bumps `CHARACTER_SCHEMA_VERSION` and adds a step to `migrateCharacter` with a test.
- Every new left-rail panel needs a Help topic (`helpTopics.test.ts`).

## 3. Architecture

```
src/character/
  schema/   types.ts (Character, Body, Pose, Camera…), parse.ts (validate + defaults), migrate.ts, ids.ts
  rig/      skeleton.ts (24 joints, bone lengths from the body), math.ts (vec3 / mat3), fk.ts, ik.ts (two-bone),
            limits.ts (joint limits), poseOps.ts (mirror, blend, toKeyframes), grounding.ts (foot contact)
  render/   camera.ts (projection, shots, view bins), shapes.ts (capsule, hull, rounding), body.ts (parts from the
            posed skeleton), face.ts (2.5D head features), styles.ts (style token packs), toSvg.ts (string export)
  data/     poses/*.ts (pose DSL + library), recipes.ts, palettes.ts (skin, hair, clothes)
src/store/slices/createCharacterSlice.ts      library, active character, camera, history, autosave, place on page
src/lib/storage/characterStorage.ts           the character library in IndexedDB
src/components/organisms/character/           CharactersPanel (left rail), CharacterStudio (full-screen workspace)
```

Data flow: recipe / saved JSON → `parseCharacter` → slice (`activeCharacter`) → `renderCharacter(character, camera)`
(pure) → `RenderModel { parts[] }` → `<CharacterView>` (SVG) or `toSvg()` (string) → board (Fabric group).

## 4. Contracts

```ts
Character = { schemaVersion, id, name, source: 'recipe'|'custom'|'imported', recipeRef?,
  body: { height, fat, muscle, shoulderWidth, hipWidth, armLength, legLength, neckLength, age, gender, skinTone,
          overridden: string[] },          // sliders 0..1 (UI 0..100); age in years 5..80; gender 0 male … 1 female
  face: { eyeStyle, eyeColor, browStyle, mouthStyle, noseStyle },     // full face system: phase 2
  hair: { style, color },                  // library: phase 3
  dress: { top: { kind, color }, bottom: { kind, color }, shoes: { kind, color }, accessories: [{ kind, color }] },   // schema v4 (wardrobe)
  emotion: { id, intensity },              // phase 2
  rig: { pose: Pose },                     // the current pose
  style: 'cartoon'|'anime'|'realistic'|'manga'|'webtoon' }
Pose = { id, name, tags[], category, rootOffset{x,y,z}, rootRotation{yaw,pitch,roll}, joints{ [JointId]: {x,y,z} },
  handShapeL, handShapeR, headLook{yaw,pitch}, ground: 'both'|'left'|'right'|'air', mirrorable }
Camera = { yaw 0..360, pitch -70..70, roll, shot: 'full'|'knee'|'waist'|'bust'|'closeup' }
```

- Keyframe paths for the Timeline: `rig.<joint>.x|y|z`, `rig.root.yaw`, `face.mouth.viseme`, `face.eyes.open`,
  `emotion.intensity`; continuous values interpolate, discrete ones step.
- **Board contract:** "Place on page" adds a Fabric group (origin center, at the view centre, drawn at a fixed
  2.2 px per cm × the page's creation scale, so sizes are true) with `characterData` = `{ character, camera }`.
  Selecting it and opening the studio edits it; "Update on page" puts the new drawing into the same group (its id,
  animation track, notes, connectors, locks, layer, centre, scale and turn stay), one undo step.
- Placement contract with the Room Builder (later): `{ x, y, scale, layer: 'behindFurniture'|'mid'|'frontFurniture',
flipX }`.

## 5. Phases and acceptance checks

**Phase 1 (foundation)**: schema + parse + migrate; 24-joint skeleton with proportions from body and age (head ratio
1:5 kid → 1:7.5 adult); FK, two-bone IK, joint limits, mirror, blend, pose → keyframes; foot-contact grounding;
camera (yaw, pitch, shots) with 3 view bins; cartoon style; body sliders (height, fat, muscle, shoulders, hips, arms,
legs, neck, age, gender), 12 skin tones, 3 hair styles, base clothes per segment (top, bottom incl. skirt, shoes);
40 poses; 12 recipes; undo 30 + autosave; studio UI (Cast, Body, Poses; camera bar; part select + recolor);
characters panel; place / update on page.
Checks: FK / IK / limits / mirror / blend / projection / migration / undo / recipe uniqueness unit tests; a pose on a
child, an adult and an elder keeps both feet on the ground (`ground: 'both'`); yaw 0…360 in 15° steps never
produces NaN or a detached limb (joint chains stay connected); style field change only changes `style`; a placed
character survives undo, reload and a page switch; E2E: open, pick a recipe, pose, rotate, place, reload, edit, update.

**Phase 2 (face and styles)**: face system on the 2.5D head (eye layers, blink, gaze, pupil, brows, nose, mouth, ears,
face-shape morph), 20 emotions as parameter vectors, visemes + `setViseme`, auto blink; 5 view bins with art variants;
anime, realistic, manga B/W (screentone from `lib/comic/screentone`), webtoon styles; 120 poses. Animation engine:
rig tracks on placed characters (paths above). _Ask:_ none expected.

**Phase 3 (content)**: hair (40 styles from layered parts, two-tone), garments per segment with fit and folds (80
items → 50+ outfit presets), conflict rules, cast generator to 100 (seeded, uniqueness test), Cast Browser filters,
250 poses, two-character poses with pair anchors, extreme-angle head keyshapes. _Ask:_ none expected.

**Phase 4 (import and story)**: rig-ready SVG import (group-name convention, pivot confirm), PNG cut-out wizard with
mesh warp, turnaround / model sheet, manga page and webtoon strip composers (or reuse the Comic panel), bubbles, SFX,
exports. _Ask:_ PSD reader and PDF writer dependencies.

**Phase 5 (polish)**: pose capture from a photo (_ask:_ MediaPipe dependency, model download, licence), secondary
motion springs, movement clips for the Timeline, mobile bottom sheets, performance pass (`timed()` around render;
slider drag ≤ 16 ms per update on the 500-object board), README / extension guide (add a pose, outfit, garment,
recipe, style pack).

### 7.3 Style pack contract (built in S1, grows in phase 9)

`StylePack = { id, name, tags, line { width, color: darken | ink | none, darken, silhouette }, shading { kind: none |
cel | soft, strength, offset }, rim?, hairHighlight?, hairGradient?, clothGradient?, palette: color | manga, proportion
{ headScale }, eyes { scale, tall, iris, shine }, face { chin: round | pointed, featureLine }, boardOutput: vector |
raster }`. Shading is drawn as shapes, not filters: a part's shadow is the part minus itself shifted toward the
light (a crescent that always stays inside the outline); soft = 3 lighter bands; rim and hair highlights are thin
crescents. So every pack in S1 is `vector` and stays editable on the page. Character JSON changes only in `style`.
The 20 ids: `cartoon`, `indian-tv`, `anime`, `anime-90s`, `manga`, `webtoon`, `chibi`, `doodle`, `sketch`, `comic-western`,
`flat`, `realistic`, `watercolor`, `cel-3d`, `pixel`, `picture-book`, `noir`, `paper-cut`, `cyberpunk`, `stick`.

### 7.4 Acceptance checks (each one a named test)

The brief's ten checks stay, made testable: real-height ratio at equal depth and after moving back (unit, `scene.test`);
ground drag keeps feet at y = 0 and draw order against 4 actors (unit + E2E); 5-actor two-row class photo with no
limb crossing another actor's torso (unit on projected capsules); group hug / arm-round-shoulder hands within 1 cm of
the target shoulder for heights 120–190 cm (unit); 20 styles leave Scene JSON identical except style ids (unit);
corner / isometric views use one projection for set and actors (unit: a set box corner and an actor's foot project
through the same matrix); top view renders every character / outfit (unit sweep); photo calibration scale within 5 %
(unit on a synthetic photo); 5 + 30 + background frame time under the throttled budget (E2E perf); all tests pass.

## 9. Scene architecture (decided 2026-11-18, owner: "take decisions as senior architect")

The owner asked for scenes and backgrounds next, built for a big project: scalable, reusable, easy to maintain and
test. These decisions bind phases 6–10; change them only with a new row in docs/DECISIONS.md.

### 9.1 Modules and boundaries

```
src/scene/                         pure TypeScript: no React, no Fabric, no store (guard: domainBoundaries.test.ts)
  schema/   types, parse (never throws, defaults + clamps, SCENE_SCHEMA_VERSION + migrate)
  camera/   projection (world → frame, frame → ground, near-plane clipping, horizon, vanishing points), named views
  world/    seeded random, time of day / weather / season → one light, sky and colour grade
  sets/     set-piece primitives, builder helpers, card silhouettes, environment registry, environments/<id>.ts
  layout/   formations (data), arrange (rows by height, align, distribute, nudge), look-at
  render/   renderScene (pure: Scene → SceneModel), set / actor / guide / weather / frame renderers, toSvg
  studio/   SceneEdit (a discriminated union) + applySceneEdit (pure), the store calls it
  board.ts  the only Fabric file: SceneModel → a Fabric group carrying `sceneData` (CUSTOM_PROPS)
src/character/                     the same rule (its board.ts is the only Fabric file)
store/slices/createSceneSlice.ts   studio scene state + actions; logic lives in src/scene/studio
components/organisms/scene/        Scene mode UI inside the Character Studio
```

- **One renderer, three consumers** (studio view, SVG / download, the page), like characters: they cannot disagree.
- **Content is data in registries** (`Registry<T>`: unique ids, lookup, tag search). Environments, formations, card
  shapes, named views, aspect ratios. Every registry has a **contract test** that runs over all entries (renders,
  finite numbers, inside the frame, unique ids, a name), so entry 101 is covered the day it is added.
- **Deterministic**: every generator takes a seed (`mulberry32`); the same Scene JSON always draws the same paths
  (tests, undo, the page, collaboration later).
- **Versioned data**: Scene JSON embeds full Character JSON per actor (a scene is self-contained; a library
  reference is a later optional field). `parseScene` repairs anything; unknown newer versions are refused.
- **File budgets** hold by design: one environment per file, one renderer per primitive kind.

### 9.2 Projection

- World = rig space: cm, y up, ground y = 0, +x = right of the default view, +z toward the default camera.
- `SceneCamera = { position, yaw, pitch, roll, lens: perspective(focalMm) | orthographic(heightCm) }`, rotation
  identical to the studio orbit (`viewMatrix`). Frame = 1000 units wide, height by aspect; focal length on a 36 mm
  sensor (`f = focalMm / 36 × 1000`).
- **Set pieces: true perspective**, per vertex, clipped at the near plane (lines stay straight, boxes are exact).
- **Actors: per-actor perspective.** Each actor is drawn by the existing character renderer from the direction the
  camera sees it (relative yaw / pitch from the camera ray), then placed with a 2D similarity: scale = focal /
  distance, rotation = the projected vertical at its feet, position = its projected ground point. Feet and set use
  the same matrix (acceptance check), real height ratios hold, every style pack works unchanged, renders cache per
  actor and per place (bounded LRU: a drag re-renders one actor; crowds). Not modelled: foreshortening inside one
  actor (a near hand bigger than a far one); a per-joint projector can replace it later behind the same `placeActor`
  seam.
- **Draw order**: sky → ground and ground marks → set pieces, contact shadows and actors sorted far to near →
  `front` pieces → weather → frame border. Guides are studio-only, never exported.
- **One light**: time of day gives a sun direction; boxes shade by face normal, actors get it projected into their
  view as the style packs' screen light, so the cel shadows fall the same way as the set's.
