# Bug audit

Audit date: 2026-11-06. Static review only: nothing was run in a browser.
Batch 1 (same day): type-check, lint and the new unit tests were run; see TESTING.md for how.
Severity: **Critical** = data loss, a core flow broken, or CI blind. **Medium** = wrong behaviour with a workaround,
or a latent defect that a planned fix will expose. **Minor** = hygiene, performance or dead code.

Status values: `open` · `fixed (<commit/PR>)` · `wontfix (<reason>)`. When you fix a bug, change its status here and
add the regression test named in the "Test needed" column.

Coverage: every store slice, `CanvasBoard`, the animation engine/export, the pages/layers/animation panels and the
toolbar/command wiring were read line by line. The large feature modules (`createNodeEditorSlice`,
`advanceOperationSlice`, `createShapeStyleSlice` boolean ops, `GradientTool`, `shapeConnectors`, `ExportCanvas`,
`TemplateGallery`, marketing pages) were read in part and checked with targeted searches. **Expect more bugs in them.**

Key-collision data comes from an AST scan (not committed) of every slice's returned object, in the spread order of
`src/store/index.ts`. See [STATE.md](STATE.md#key-collisions).

**Status 2026-11-09:** every bug in this audit is fixed except **BUG-136** (deferred, dev tooling only, see its row).
New bugs get the next free ID and start as `open`.

**Status 2026-11-11 (whole-app review):** the review ran the code, not only read it. Five new bugs were found and
fixed with tests (BUG-154 to BUG-158) and BUG-152 was closed. Seven more were found by reading the code and are
`open` (BUG-159 to BUG-165): each needs an owner decision or is a larger change. They were not reproduced in a
browser.


**Archive (2026-11-13):** fixed bugs moved to [BUGS_ARCHIVE.md](BUGS_ARCHIVE.md) to keep this file short to read. This
file lists only bugs that are not fixed. Highest ID so far: **BUG-208**; new bugs take the next one. Look up any
ID with `grep -n "BUG-0xx" docs/BUGS*.md`. When you fix a bug, move its row to the archive with its new status.

Saved boards can then vanish. Suggested: ask after the first saved change (Chrome decides silently; Firefox shows a permission prompt, so when to ask is an owner decision) and keep reminding users to Save a copy. ## Fabric 7 notes (not bugs yet; verify while fixing)

- `stopContextMenu`, `fireRightClick` and `fireMiddleClick` are deprecated in v7 and their defaults changed (Fabric changelog #10720). `CanvasBoard` relies on the `contextmenu` canvas event. **UNKNOWN - verify** that right-click still selects and opens the menu.
- Text positioning changed (#10803). Saved boards from v6 may render text slightly differently. **UNKNOWN - verify.**
- `canvas.clear()` does **not** reset `canvas.clipPath` (checked in Fabric 7.1 source); `loadFromJSON` does (its enlivened map always carries `clipPath`, `undefined` when absent), so undoing a template removes its clip.
